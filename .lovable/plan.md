# خطة توحيد الموقع بين Lovable و Vercel

الهدف: نسخة Vercel تطابق نسخة Lovable 100% — نفس المحتوى، نفس الصور، نفس رمز لوحة التحكم.

## نقطة مهمة قبل البدء

اخترت أن نبقي قاعدة بيانات Lovable الحالية كمصدر وحيد. هذا يعمل لكل الجزء العام (الشخصيات، الأحداث، الصور، الستريمرز)، لكن هناك قيد واحد حقيقي:

لوحة التحكم والبوابة السرية تحتاج مفتاح إداري خاص بقاعدة البيانات، وهذا المفتاح لا يمكن قراءته أو استخراجه من Lovable نهائيًا. يعني: على Vercel سيظهر الموقع بكل محتواه، لكن لوحة التحكم وصفحة التحقق لن تعملان هناك.

لذلك أمامك مسارَان، وأنا أوصي بالثاني:

- **مسار أ (كما اخترت):** نبقي قاعدة Lovable. Vercel يعرض المحتوى كامل، والتحكم يبقى من Lovable فقط.
- **مسار ب (موصى به للتطابق 100%):** ننقل كل شيء إلى حساب Supabase الجديد الذي أنشأته. هناك تملك جميع المفاتيح بنفسك، فيصبح Lovable و Vercel متطابقين تمامًا بما يشمل لوحة التحكم.

المحتوى في الحالتين يُنقل كاملًا كما طلبت (11 شخصية، 10 أحداث، 58 صورة، الإعدادات، والاقتراحات).

## المفاتيح: ماذا نأخذ وماذا نصنع

المفاتيح الأربعة التي عندك:

| ما عندك | لماذا يُستخدم |
| --- | --- |
| Project URL | عنوان قاعدة البيانات |
| Publishable key | مفتاح القراءة العام (آمن في المتصفح) |
| Direct connection string | لنقل البيانات مرة واحدة فقط، لا يُخزَّن في Vercel |
| CLI setup commands | غير مطلوبة لنا |

مفتاحان ناقصان يجب أن تجلبهما من إعدادات مشروعك في Supabase (قسم API Keys):

- **Service role key** — المفتاح الإداري الذي تحتاجه لوحة التحكم. سري، لا يوضع أبدًا في كود المتصفح.

ومفتاحان نصنعهما نحن (قيمة عشوائية طويلة، تُستخدم بنفسها في Lovable و Vercel):

- **رمز تشفير جلسة البوابة**
- **ملح التشفير الخاص برمز الدخول والصورة السرية** — مهم: إن اختلف هذا بين النسختين، فرمزك وصورتك السريان لن يعملا على النسخة الثانية. لذلك نفس القيمة في المكانين، كما اخترت.

## الخطوات القادمة بالترتيب

1. تختار المسار (أ أو ب).
2. تسلّمني المفاتيح بالطريقة الآمنة داخل Lovable (لا تكتبها في المحادثة): Project URL، Publishable key، Service role key، وسلسلة الاتصال المباشر إن اخترنا النقل.
3. أُنشئ قيم التشفير الطويلة وأعطيك نسخة تلصقها في Vercel.
4. إن اخترت المسار ب: أنقل الهيكلة والصلاحيات والدوال، ثم المحتوى والصور، وأتحقق من الأعداد بعد النقل.
5. أضبط قائمة المتغيرات في Vercel وأعطيك إياها جاهزة للصق.
6. نجرّب على Vercel: الصفحة الرئيسية، الشخصيات، الأحداث، الستريمرز، ثم البوابة ولوحة التحكم على الجوال وسطح المكتب.

## تفاصيل فنية

متغيرات البيئة المطلوبة في Vercel (Production + Preview):

```text
VITE_SUPABASE_URL            = Project URL
VITE_SUPABASE_PUBLISHABLE_KEY= Publishable key
VITE_SUPABASE_PROJECT_ID     = معرّف المشروع
SUPABASE_URL                 = نفس Project URL
SUPABASE_PUBLISHABLE_KEY     = نفس Publishable key
DB_SERVICE_KEY               = Service role key
GATE_SESSION_SECRET          = قيمة عشوائية 64 حرفًا
GATE_HASH_SALT               = نفس القيمة المستخدمة في Lovable
```

الكود يدعم هذا أصلًا: `src/lib/env.server.ts` يقرأ الأسماء البديلة `DB_SERVICE_KEY` و`GATE_SESSION_SECRET` و`GATE_HASH_SALT` ويفضّلها على الأسماء المُدارة، وهو ما يسمح بتطابق البيئتين دون تعديل كود.

نقل البيانات في المسار ب: تطبيق migration الهيكلة أولًا (الجداول + GRANT + RLS + دوال البوابة)، ثم نسخ صفوف `blocks` و`block_images` و`site_settings` و`suggestions`، ثم تنزيل ملفات bucket `block-images` و`suggestion-images` ورفعها إلى المشروع الجديد بنفس المسارات حتى تبقى السجلات صحيحة. بيانات الزوار والتحققات لا تُنقل (تُولَّد من جديد).
